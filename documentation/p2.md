# P2 Text Processing and Indexing

## Overview

P2 is responsible for converting raw Hindi/Hinglish news text into searchable representations.

The P2 pipeline currently consists of:

1. normalization
2. tokenization
3. stemming
4. positional indexing
5. zone-aware postings
6. Boolean retrieval
7. phrase/proximity retrieval
8. query integration

---

# 1. Normalization

Input text is normalized using Unicode NFC normalization.

Additional normalization handles:

- zero-width joiners
- zero-width non-joiners
- the specified Hindi spelling normalization

Whitespace is collapsed.

The normalizer avoids indiscriminate anusvara conversion because this can alter valid Hindi words.

---

# 2. Tokenization

The tokenizer uses Unicode-aware regular expressions.

Pattern:

    [\p{L}\p{M}\p{Nd}]+

This captures:

- Unicode letters
- Unicode combining marks
- Unicode decimal digits

Punctuation is excluded.

---

# 3. Analysis modes

The analyzer exposes:

    analyze(text, mode)

Current modes:

| Mode | Behavior |
|---|---|
| none | normalization + tokenization |
| light | normalization + tokenization + light stemming |
| aggr | normalization + tokenization + aggressive stemming |

The analyzer returns:

    [(term, position), ...]

Positions are zero-based token positions.

---

# 4. Positional index

Each index stores postings by term and zone.

Zones:

- headline
- body

A posting is:

    (doc_id, tf, positions)

Example:

    ("doc1", 2, [1, 4])

means that the term occurs twice in `doc1`, at positions 1 and 4.

---

# 5. Document metadata

Each document stores:

- source
- date
- state
- section
- dup_of

This metadata is preserved from the article JSONL input.

---

# 6. Boolean retrieval

Boolean AND retrieval returns only documents containing all query terms.

The implementation uses the smallest postings list first.

This is important because intersecting the smallest candidate set first reduces subsequent work.

---

# 7. Skip pointers

Skip pointers are used to reduce the number of postings examined during list intersection.

They are particularly useful when postings lists differ substantially in size.

---

# 8. Phrase retrieval

Because positions are stored, the index supports phrase queries.

A phrase is matched by checking whether the query terms occur in the required positional sequence.

---

# 9. Proximity retrieval

The index also supports proximity queries.

The current implementation checks whether all query terms occur within the requested positional distance from an anchor term.

---

# 10. Query integration

The query layer converts a raw query into analyzed terms before retrieval.

Example:

    search_query(
        idx,
        "दिल्ली बारिश",
        mode="light"
    )

The analyzer mode must match the index mode.

---

# 11. JSONL index construction

The index builder reads:

    data/news.jsonl

Required fields:

    doc_id
    headline
    body

The builder supports:

    none
    light
    aggr

Indexes can be generated using:

    python -m index.build --mode none
    python -m index.build --mode light
    python -m index.build --mode aggr
